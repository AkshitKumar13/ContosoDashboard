# Data Model: Document Upload and Management

## Document

Represents a stored work-related file.

| Field | Type | Rules |
|---|---|---|
| DocumentId | int | Primary key; generated by the database. |
| Title | string | Required; bounded length; user-visible label. |
| Description | string? | Optional; bounded length. |
| Category | string | Required; one of the six approved text values. |
| Tags | string? | Optional; normalized tag representation. |
| OriginalFileName | string | Display-only metadata; never used as a storage path. |
| FilePath | string | Required relative storage key; unique generated value. |
| FileSize | long | Required; 0 < size <= 25 MB. |
| ContentType | string | Required; validated MIME type; max 255 characters. |
| UploadedDate | DateTime | Required UTC timestamp. |
| UpdatedDate | DateTime | Required UTC timestamp. |
| UploadedByUserId | int | Required foreign key to User. |
| ProjectId | int? | Optional foreign key to Project. |
| TaskId | int? | Optional foreign key to TaskItem; task association requires matching project. |

Relationships:
- One User uploads many Documents.
- One Project has many Documents.
- One TaskItem has many Documents.
- Document access is derived from owner, current project membership, administrator scope, and DocumentShare records.

## DocumentShare

Represents an explicit sharing grant to a user or an existing department/team.

| Field | Type | Rules |
|---|---|---|
| DocumentShareId | int | Primary key. |
| DocumentId | int | Required foreign key to Document. |
| SharedWithUserId | int? | Direct recipient; mutually exclusive with department. |
| SharedWithDepartment | string? | Existing User.Department value; mutually exclusive with user. |
| SharedByUserId | int | Required actor foreign key to User. |
| SharedDate | DateTime | Required UTC timestamp. |

Rules:
- Exactly one recipient target is required.
- Direct shares remain after project membership ends until revoked.
- Duplicate active grants for the same document and target are not allowed.
- The share is persisted even if notification delivery fails; delivery is retried.

## DocumentActivity

Append-oriented audit record retained for 12 months.

| Field | Type | Rules |
|---|---|---|
| DocumentActivityId | int | Primary key. |
| DocumentId | int? | Nullable so failed or deleted-document activity can remain attributable. |
| ActorUserId | int | Required foreign key to User. |
| Action | string | Required controlled text: Upload, Download, Delete, Replace, MetadataUpdate, Share. |
| Details | string? | Optional bounded context such as recipient or file type. |
| CreatedDate | DateTime | Required UTC timestamp; indexed for retention/reporting. |

## Controlled Values

Categories:
- Project Documents
- Team Resources
- Personal Files
- Reports
- Presentations
- Other

Supported content types are mapped from the allowed PDF, Office, text, JPEG, and PNG extensions and validated against both extension and MIME type.

## State and Transaction Rules

1. Validate metadata, size, extension, MIME type, authorization, and scan result before availability.
2. Generate a unique relative path, save the file, then persist metadata.
3. If metadata persistence fails after file save, attempt file cleanup and return failure.
4. Replacement writes a new safe path and only switches metadata after the new file passes validation and scan; the old file remains available until the switch succeeds.
5. Delete metadata and file with explicit cleanup handling; no recoverable trash is in scope.
6. Retention removes or archives activity records older than 12 months without deleting current document metadata.
